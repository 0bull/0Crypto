When a new version of 0Crypto comes out, your deployment does not change by itself. You pull the new version into your GitHub copy, and Cloudflare rebuilds the gateway. Database changes run first, then the new code goes live.

## Update a gateway made with the button

<Steps>

1. **Back up first.** On your computer, in your copy of the repository, run `npx wrangler d1 export DB --remote --output backup.sql`. Keep the file. See [Security and backups](/docs/security/).

2. On GitHub, open your copy of the 0Crypto repository. Use **Sync fork** (or merge the original repository into yours) to bring in the newest version. Check the original repository for any release notes or new settings.

3. Cloudflare rebuilds and deploys. In the Cloudflare dashboard open Workers & Pages, **0crypto**, Deployments, and wait for the new one to show as successful. If a database change fails, the new code is not deployed and the old gateway keeps running.

4. Open your admin. Look at the alerts on the Overview, then check the Wallets and (if you use it) Privacy routing pages.

</Steps>

If you deployed by hand instead of with the button, run `npm run deploy` in your copy. It applies the database changes first and then deploys. (`npm run deploy:first` does it in the other order and is only for the very first deploy.)

Never change your seed phrase during an upgrade. If your hot wallet addresses changed on the Wallets page, something is wrong.

If you edited `wrangler.jsonc` in your copy (routed mode or privacy routing settings), check those settings after syncing. GitHub may ask you to resolve a clash if the same lines changed.

## Reset a local test database

If you run 0Crypto on your own computer for development, a new version may change the database in a way old test data cannot follow. The local database is only for testing, so you can reset it. In the repository folder run `rm -rf .wrangler/state` and start again. This deletes only your local test data, never a deployed gateway.

:::caution
Do not use this on a live gateway. A deployed gateway keeps its data in Cloudflare, and this command does not touch it.
:::

:::tip[You should now see]
The latest deployment on Cloudflare shows as successful, your admin opens and you are still signed in or can sign in with your passkey, and no new alert is waiting on the Overview.
:::
