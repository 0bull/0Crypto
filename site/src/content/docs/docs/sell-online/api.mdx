This page is for developers. If you use WooCommerce or payment links you do not need it.

The API is JSON over https. Your gateway address is called `https://pay.example.com` below. Replace it with yours. Amounts are decimal strings, never numbers.

## Get an API key

<Steps>

1. Open **API keys & webhooks** in your admin (the page is titled **Developers**).

2. In the **New API key** box, type a **Label** such as "shop-prod", press **Create key** and confirm with your passkey.

3. Copy the key. It starts with `0c_live_` and is shown once ("Copy it now. It won't be shown again."). Keep it on your server only. **Revoke** in the list turns a key off.

</Steps>

Send it with every authenticated call as `Authorization: Bearer 0c_live_...`.

## Create an invoice

```sh
curl -X POST https://pay.example.com/api/v1/invoices \
  -H "Authorization: Bearer $KEY" -H "content-type: application/json" \
  -d '{"price_amount":"50.00","price_currency":"USD","order_id":"1001"}'
```

The answer contains a `checkout_url`. Send the customer there.

Fields:

- `price_amount` (required): up to 2 decimals, more than 0 and at most 1000000.00.
- `price_currency` (required): `USD` or `EUR`.
- `order_id`: your own reference.
- `metadata`: an object of up to 4096 bytes. The keys `pos`, `link_id` and `subscription_id` are reserved.
- `success_url`: an https address to send the customer to after payment. If you list hostnames under **Settings**, **Success URL hosts**, it must be on one of them (exact host, no subdomains, port ignored). Add `localhost` to the list too if you test on your own computer. The list applies to invoices created after you save it.
- `allowed_assets`: a list of enabled coin ids, such as `btc:btc`.
- `expires_in_sec`: 300 to 86400, default 3600.

## Read an invoice, list coins, start a payment

```sh
# Status, paid amount and payments
curl https://pay.example.com/api/v1/invoices/$INVOICE_ID -H "Authorization: Bearer $KEY"

# Coins you currently accept (no key needed)
curl https://pay.example.com/api/v1/assets

# Pick a coin: locks the rate for 20 minutes and returns the address and amount
curl -X POST https://pay.example.com/api/v1/invoices/$INVOICE_ID/payments \
  -H "content-type: application/json" -d '{"asset":"btc:btc"}'
```

## Payment links

```sh
# Create. Leave out price_amount for an open-amount link.
curl -X POST https://pay.example.com/api/v1/links -H "Authorization: Bearer $KEY" -H "content-type: application/json" \
  -d '{"title":"Workshop ticket","price_amount":"25.00","price_currency":"EUR","allowed_assets":["btc:btc","ln:btc"]}'

# List, newest first (?limit=1-100, ?cursor= from next_cursor)
curl "https://pay.example.com/api/v1/links?limit=50" -H "Authorization: Bearer $KEY"

# Deactivate (send true to reactivate)
curl -X PATCH https://pay.example.com/api/v1/links/$LINK_ID -H "Authorization: Bearer $KEY" -H "content-type: application/json" -d '{"active":false}'
```

## Subscriptions

```sh
# Create. start_at is ISO 8601 or unix milliseconds and sets the time of day and the day of the month.
curl -X POST https://pay.example.com/api/v1/subscriptions -H "Authorization: Bearer $KEY" -H "content-type: application/json" \
  -d '{"label":"Pro plan","price_amount":"19.99","price_currency":"USD","interval":"monthly","start_at":"2027-01-31T09:30:00Z","metadata":{"customer":"c_42"}}'

# List, paged like links
curl "https://pay.example.com/api/v1/subscriptions" -H "Authorization: Bearer $KEY"

# Deactivate (history is kept)
curl -X DELETE https://pay.example.com/api/v1/subscriptions/$SUB_ID -H "Authorization: Bearer $KEY"
```

## Errors

Errors look like `{ "error": "<code>", "message": "..." }`.

| Code | Status | Meaning |
|---|---|---|
| `unauthorized` | 401 | Missing or wrong key |
| `invalid_request` | 400 | A field is wrong |
| `asset_not_allowed` | 400 | That coin is not allowed for this invoice |
| `not_found` | 404 | No such invoice, link or subscription |
| `invoice_closed` | 409 | The invoice is already paid or expired |
| `payment_in_progress` | 409 | A payment is already open |
| `rate_limited` | 429 | Slow down |
| `price_unavailable` | 503 | No fresh exchange rate yet |
| `lightning_unavailable` | 503 | The Lightning wallet did not answer |
| `internal_error` | 500 | Something failed on the gateway |

## Verify a webhook

Webhooks are described in plain words on the [webhooks page](/docs/webhooks/). Each one has this header:

```
0Crypto-Signature: t=<unix seconds>,v1=<hex>
```

To verify, take the raw body before any JSON parsing and compute HMAC-SHA256 over the string `<t>.<body>`. The key is your whole webhook secret, including the `whsec_` prefix. Hex-encode the result and compare it with `v1` in constant time. Reject the request if `t` is more than 5 minutes from your clock.

```js
import { createHmac, timingSafeEqual } from "node:crypto";

export function verify(secret, header, rawBody, toleranceSec = 300) {
  const parts = Object.fromEntries(header.split(",").map((p) => p.trim().split("=")));
  const t = Number(parts.t);
  if (!parts.v1 || !Number.isFinite(t)) return false;
  if (Math.abs(Date.now() / 1000 - t) > toleranceSec) return false;
  const expected = createHmac("sha256", secret).update(`${parts.t}.${rawBody}`).digest("hex");
  const a = Buffer.from(expected), b = Buffer.from(parts.v1);
  return a.length === b.length && timingSafeEqual(a, b);
}
```

The body is `{ "id", "type", "created_at", "data" }`, where `data` is the invoice as the API returns it. Events about refunds and about routed funds carry a refund or batch object instead. `webhook.test` has an empty `data`. Deduplicate by `id`.

The create-invoice call answers with an invoice that has a `checkout_url`. Opening it shows a checkout page, and your webhook handler accepts a signed test event.
:::
